# ADR: Go with vendored mactop collectors for wattop

- **Date**: 2026-09-06
- **Status**: Accepted
- **Deciders**: Jason, on a unanimous two-judge verdict over three researched proposals

## Context

The dashboard has to do two things nothing in the ecosystem currently does together: read Apple Silicon telemetry at mactop's depth (per-cluster CPU, GPU, ANE, power, temperatures, thermal state, memory, network, disk) and read live AI coding-agent session state (Claude Code and Codex CLI: busy/waiting, model, tokens, context fill, cost, burn rate, tool calls, subagents) — then **join the two by pid on one refresh clock**. A prior research pass confirmed the gap is real: Apple Silicon monitors know nothing about agents, and the "htop for AI agents" TUIs derive their system half from `ps`, so none of them has GPU, ANE, power or thermal data at all. Running mactop beside abtop in two tmux panes gives two processes, two clocks and zero shared state, which structurally cannot answer "that GPU spike was *that* session".

Constraints for v1: realtime at 1–2 s, no sudo, single user, macOS arm64 only. Available toolchains on the machine: Go 1.27.0, Rust 1.95.0, Node 24. Jason's stack defaults favour Go or Rust for TUIs and forbid an OpenAI runtime dependency in shipped code.

Three proposals were researched and then scored by two independent judges, each of whom re-ran the contested claims on this machine.

## Decision

**Go 1.27 with CGO, targeting darwin/arm64 only, vendoring mactop's collector layer in-process.**

- **TUI**: `charm.land/bubbletea/v2 v2.0.9` + `charm.land/lipgloss/v2 v2.0.6` + `charm.land/bubbles/v2 v2.2.1` + `github.com/NimbleMarkets/ntcharts/v2 v2.2.0`. All four confirmed against proxy.golang.org on 2026-09-06. The Charm v2 modules live on `charm.land/*`, not `github.com/charmbracelet/*`; `bubbles/v2` requires the `charm.land` form, so mixing the two produces a module-path error.
- **System metrics**: 15 files copied from mactop's `internal/app` into `internal/soc/vendor` under MIT (Copyright © 2024-2026 Carsen Klock), behind a `Sampler` interface. mactop is **not importable** — every collector sits under `internal/`, so vendoring is the only route.
- **Process metrics**: a hand-written CGO scanner using `sysctl(KERN_PROC_ALL)`, `proc_pidinfo(PROC_PIDTASKINFO)` and `proc_pid_rusage(RUSAGE_INFO_V4)`. No gopsutil.
- **Pricing**: LiteLLM's `model_prices_and_context_window.json`, filtered and embedded with `go:embed`, refreshed asynchronously with a 24 h TTL.
- **Distribution**: one binary with no external runtime — no Node, no Python, no subprocess, macOS system frameworks only. It is **not** a static binary: CGO links CoreFoundation, IOKit and the private `-lIOReport` dynamically, so it cannot be cross-compiled and releases build on `macos-latest`.

What decided it was not an argument but a run. The proposal extracted the 15 files into a fresh module, compiled them with one 20-line shim plus six mechanical edits, and executed the result unsigned and passwordless, printing live IOReport power, SMC temperatures, cluster activity, GPU frequency and a **27-entry per-pid GPU table**. A separate 60-line CGO probe returned per-pid CPU nanoseconds and RSS. Every headline capability was demonstrated on this machine before it was estimated.

## Alternatives considered

### Rust 1.95 + ratatui 0.30.2 + macmon 0.8.2 as a library

Scored 53 and 51. Genuinely attractive: macmon ships a real `[lib]` target at `src_lib/lib.rs` with the binary gated behind `required-features = ["app"]`, leaving only `core-foundation`, `libc`, `serde` and `serde_json` — the cleanest dependency story of the three, with the hard half tracked by semver instead of owned. `ratatui-themes` 0.3.0 supplies 16 named palettes for free.

Rejected on two grounds. First, a load-bearing false negative: it asserted per-session GPU is impossible without sudo and pre-attacked the other proposals on that basis. Both judges disproved it by measurement — `mactop --headless --format json --count 2` returns nonzero `gpu_ms_per_sec` for ordinary user pids without sudo, and the winner read a larger table in-process. The impossibility was reached through `task_for_pid`, the wrong API for this data, and through a `--count 1` sample whose deltas are structurally zero. Second, its clean adapter is clean partly because it drops requirements: macmon's curated `Metrics` carries no network or disk throughput, so those become hand-written IOKit code in Rust — the same Apple-internals class the Go option was docked for owning, but without mactop's already-working implementation underneath. Reaching per-pid GPU would likewise mean going past `Metrics` into macmon's raw `IOReport::new` re-exports against a 135-channel group, undesigned and absent from its estimate.

It also chose models.dev over LiteLLM on the false belief that LiteLLM lacks bare model keys. models.dev has no `cache_creation_input_token_cost_above_1hr` field, so that choice forced a hardcoded 2.0× derivation of the 1-hour cache-write rate — a wrong fact producing a worse design.

Kept for v0.2: macmon as a second implementation of the same `Sampler` interface, as a cross-check oracle on chips other than M5 Max and a fallback if the vendored ObjC ever stops building. It costs one adapter.

### Go + subprocess `mactop --headless --format json --count 0`

Scored 46 and 46. Ships fastest and owns no Apple code; a macOS fix arrives via `brew upgrade`. Its measurement work was the most rigorous of the three, and what it measured is the case against itself.

Rejected on cost and on a structural cap. The child process costs a self-measured 6–8% of a core with RSS sawtoothing toward 1.1 GB; one judge reproduced 1,093,776 KB nine seconds in and saw it hold. A monitoring tool whose child is the machine's third-largest process gets uninstalled. More decisively, `processes[]` in headless JSON is hard-capped at exactly 20 entries sorted by CPU, so a *waiting* agent session — precisely the row the pid join exists to populate — is structurally absent, and the exact alternative (`--pid`) takes a single integer, making a fleet view unaffordable. It also puts a Homebrew binary in the dependency chain of a tool whose pitch is one binary, and its own escape hatch is to vendor mactop's IOReport code, i.e. to become the accepted option, deferring the maintenance cost rather than avoiding it.

Two of its factual errors were checkable and drove real commitments: it rejected ntcharts on a v1-module-path query when `/v2` exists at v2.2.0 requiring `charm.land/bubbletea/v2`, budgeting half a day of hand-rolled charts on the bad negative; and it specified tier-selection logic for `input_cost_per_token_above_200k_tokens` on `claude-opus-5`, a field that does not exist in LiteLLM's table.

Kept from it regardless: schema-tolerant pointer-typed decoding with a hand-degraded fixture, a `doctor` subcommand, a positive filename allowlist on the sessions directory with a planted-secret test, per-collector `recover()`, dual-framing tolerance in the fixture recorder, and labelling cost as an estimate that ignores subscription plans.

### Forking an existing agent monitor

abtop (Rust/ratatui, MIT, ~19k LOC) is the closest prior art, but it sits on `ratatui 0.29`/`crossterm 0.28` while the current theming crate pins `ratatui 0.30.2` — the release that split the crate into `ratatui-core`/`ratatui-widgets`/`ratatui-crossterm`. Forking means a major-version UI migration across ~4,700 lines before the first line of new feature, in a codebase whose system half is generic CPU/mem/load-average — exactly the half being replaced — and which has no cost dimension at all. Its *knowledge* (record-type edge cases across ~6,300 lines of collector) is worth mining for fixture scenarios under MIT with attribution; its code is not worth inheriting.

## Consequences

### Positive

- The pid join works by construction. One goroutine reads the SoC sample, the process table and the GPU table at the same instant, so "GPU is at 84% and 31 W, and it is *that* session" is a single reduce over one snapshot.
- Per-pid GPU is available for an **arbitrary** session pid, not the top 20 by CPU — the capability the subprocess route cannot provide and the Rust route believed impossible.
- One binary, no runtime, no Homebrew dependency, no subprocess to supervise, no second clock.
- Go matches mactop's own language, so the collector layer is a code lift rather than an FFI rewrite, and Bubble Tea is the most-maintained TUI framework in any language.
- Everything above `internal/soc` and `internal/proc` is pure Go over our own domain types, so roughly 80% of the code is tested on `ubuntu-latest` with no Apple hardware.

### Negative, and priced

- **`ioreport.m` is 136 KB of vendored Objective-C against the private `-lIOReport`, and it is ours forever.** Upstream mactop fixes do not flow in automatically. Mitigation: `internal/soc/VENDOR.md` pins the upstream commit SHA and lists every copied and modified file, and `make vendor-diff` re-fetches that SHA and diffs, so an upstream change is a reviewable delta rather than a silent fork. This is a real ongoing tax and the README names it.
- **Not cross-compilable.** `CGO_ENABLED=1 GOOS=darwin GOARCH=arm64` must build on an Apple Silicon host, so releases run on `macos-latest` and there is no Linux binary.
- **`-lIOReport` is private.** A future macOS can change or remove those channels; mactop's own source already carries workarounds for exactly that. The collector fails soft with a named error and a session-only view, never a hang.
- **CI can only compile-check the CGO half.** Whether IOReport is readable inside a GitHub-hosted macOS VM is untested, so live collector tests `t.Skip` when initialisation errors.
- Passwordless IOReport access is verified on **this machine only**, and nothing has been exercised on Intel, M1–M4, or a non-Max chip.

### Accepted degradations

Three named v0.1 requirements cannot be met literally on this hardware. Each ships as an honest dash rather than a fabricated number, and each has an acceptance test asserting the degradation.

- **DRAM and ANE bandwidth read 0.0 GB/s.** Measured under sustained load at count=1, 2 and 4, and reproduced independently by both judges using mactop itself. No cause attributed — mactop's macOS-27 counter-zeroing latch requires `cpuPower==0 && dramPower==0` and both were nonzero. `doctor --ioreport-groups` exists so the renamed channel can be found later.
- **There are no E-cores.** `sysctl` reports `hw.perflevel0.name = Super` (6) and `hw.perflevel1.name = Performance` (12); `e_cluster_active` is permanently 0.0. The cluster panel iterates reported topology and labels from it, so a hardcoded E/P pair never ships a dead gauge.
- **Per-session GPU ships as ms/sec.** The nanosecond delta is verified; the rescale to a system-GPU-busy percentage is read-but-not-run in every proposal, so the percent is derived, marked, and never the primary sort key.

Two more honesty constraints follow from the data rather than the stack. **Claude Code's context-window fill is an estimate** — a walk of every nested key across 12 transcripts found no window field, and `message.model` is bare even in a 1M-context session — so it renders with a `~` and a high-water-mark denominator, while Codex's, which the transcript states outright, renders exact. And **all costs are estimates** computed from a pricing table against client-reported usage; they ignore subscription plans entirely, which the footer says permanently.

### Name

`wattop` has one 0-star GitHub collision (`sravanpannala/wattop`) and is free on npm and Homebrew. Low risk, accepted. `soctop`, `agentwatt` and `burnwatt` were verified fully clear if a cleaner name is ever wanted. `codeburn` is taken by a real shipping tool and is excluded.
