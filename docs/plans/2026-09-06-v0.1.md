# wattop v0.1 — implementation plan

Date: 2026-09-06. Target: a terminal dashboard that puts Apple Silicon SoC telemetry and live AI coding-agent sessions on one refresh clock, joined by pid.

## Decision

**Build `wattop` in Go 1.27 with CGO, darwin/arm64 only, vendoring mactop's collector layer in-process.** Both judges scored the go-native proposal first (54/54 and 54) with no disagreement, so the winner is followed without a tiebreak.

The decisive evidence is that the proposal *ran* its riskiest step rather than arguing it: 15 files were extracted from mactop's `internal/app` into a standalone Go package, compiled, and printed live IOReport power, SMC temperatures, cluster activity, GPU frequency and a 27-entry per-pid GPU table — unsigned, locally built, no sudo. A 60-line hand-written CGO scanner returned per-pid CPU nanoseconds and RSS alongside it. Both judges re-verified the load-bearing structural claims independently: mactop is genuinely unimportable (every collector sits under `internal/app`, so vendoring is the only route, not a preference), and the Charm v2 stack has moved to `charm.land/*` module paths with changed `Init`/`View` signatures.

Module versions were re-confirmed against proxy.golang.org while writing this plan: `charm.land/bubbletea/v2 v2.0.9` (2026-08-19), `charm.land/lipgloss/v2 v2.0.6` (2026-08-11), `charm.land/bubbles/v2 v2.2.1` (2026-08-24), `github.com/NimbleMarkets/ntcharts/v2 v2.2.0` (2026-05-28). Local toolchain: `go1.27.0 darwin/arm64`.

### Losing options

**kilntop (Rust 1.95 + ratatui 0.30.2 + macmon 0.8.2 as a library) — 53 and 51.** Its central technical claim holds: macmon really does ship a `[lib]` target at `src_lib/lib.rs` with the binary gated behind `required-features = ["app"]`, which is the cleanest dependency story of the three. Its testing architecture and its theming were the best in the field, and both are grafted below. It lost on a load-bearing false negative: *"per-session GPU is not deliverable without sudo… any competing proposal claiming per-session GPU without sudo is wrong."* Both judges disproved it by measurement — `mactop --headless --format json --count 2` returns nonzero `gpu_ms_per_sec` for ordinary user pids (ghostty 38.75, Chrome Helper 69.79), and the winner read the same table in-process with 27 entries. The impossibility was reached through `task_for_pid` (the wrong API for this data) and through a `--count 1` sample whose deltas are structurally zero. It also believed LiteLLM lacked bare model keys, which is false, and that wrong fact forced it onto models.dev — which has no `cache_creation_input_token_cost_above_1hr` field, so it then had to derive the 1-hour cache-write rate from a hardcoded 2.0× multiplier it listed among its own drift risks. A wrong fact drove a worse design. Finally, its clean ~80-line adapter exists partly because it drops two named requirements: per-session GPU, and network/disk throughput (absent from macmon's curated `Metrics`, so `sysnet` is an unwritten hand-rolled IOKit module missing from its estimate).

**jouletop (Go + subprocess `mactop --headless --format json --count 0`) — 46 and 46.** The most rigorous measurement work of the three, and what it measured is the case against its own angle. Its child process costs a self-measured 6–8% of a core with RSS sawtoothing toward 1.1 GB — one judge reproduced 1,093,776 KB at t+9s and saw it stay there for the rest of an 18-second window. A monitoring tool whose child is the machine's third-largest process gets uninstalled. Worse for the actual product: `processes[]` in headless JSON is hard-capped at exactly 20 entries sorted by CPU, so a *waiting* Claude session — precisely the row the join exists to populate — is structurally absent, and the one exact route (`--pid`) takes a single integer, making a fleet view unaffordable. It also puts a Homebrew binary in the dependency chain of a tool whose pitch is one binary, and its own escape hatch (rung 3: vendor mactop's IOReport code) is to become the winner, deferring the maintenance cost rather than avoiding it. Two checkable falsehoods drove real design commitments: it rejected ntcharts on a v1-module-path query (the `/v2` path exists at v2.2.0 and requires `charm.land/bubbletea/v2`) and budgeted half a day of hand-rolled braille charts on that bad negative; and it specified tier-selection logic for `input_cost_per_token_above_200k_tokens` on `claude-opus-5`, a field that does not exist in LiteLLM's table.

### Grafted from the losers

From kilntop: the semantic **Roles** indirection (widgets never read a palette field; one mapping turns a palette into `idle/busy/waiting/warn/hot/chart_*/bar_*`); `RUSAGE_INFO_V4` field coverage so the process scanner also yields per-pid disk I/O and process start time; the concrete Codex pid-bind disambiguator (nearest-after start time, one rollout per pid, `(pid unknown)` rather than a drop); a `doctor --ioreport-groups` enumeration so a renamed DRAM channel can be found later; the tool's own CPU cost in the footer; the rule that the fixture boundary must be your own round-trippable type, never a dependency's; `billable_input = input_tokens − cached_input_tokens` for Codex; and a per-session context-window override rendered with a dashed bar edge when assumed.

From jouletop: schema-tolerant decode with pointer-typed optional fields and a hand-degraded fixture asserting a dash rather than a panic; a `doctor` subcommand printing which fields the collector layer actually supplies; a positive filename allowlist `^\d+\.json$` on the sessions walker *with a test that plants a fake `.key` file*; `recover()` in every collector goroutine reporting a degraded-source badge instead of killing the dashboard; dual-framing tolerance in the fixture recorder (`--count 0` emits bare NDJSON, `--count N>0` emits a JSON array); Claude Code's process name being its version string, so the display name comes from the session file and the command from argv; Codex rollout filenames being local time while records inside are UTC; and labelling cost as an estimate that ignores subscription plans.

### Deviations from the brief, on evidence

Three named MVP requirements cannot be met literally on this machine. Each ships as an honest degradation, and the acceptance tests assert the degradation rather than a number nobody can produce.

1. **DRAM and ANE bandwidth read 0.0 GB/s.** The winning proposal measured it under sustained load at count=1, 2 and 4; both judges reproduced it (`dram_read/write/combined` and `ane_read/write/combined` all zero) using mactop itself, the reference implementation. Not attributed to a cause — mactop's macOS-27 counter-zeroing latch requires `cpuPower==0 && dramPower==0` and both were nonzero. Ships as a dash plus a `doctor` line naming which IOReport channels resolved.
2. **There are no E-cores on this box.** `sysctl` reports `hw.perflevel0.name = Super` (6 cores) and `hw.perflevel1.name = Performance` (12); mactop maps M5 clusters to P and S, and `e_cluster_active` is permanently 0.0. A hardcoded E/P gauge pair ships a dead bar on the user's own laptop. The cluster panel iterates whatever clusters the topology reports and labels from it.
3. **Per-session GPU ships as ms/sec, not percent.** The nanosecond-delta step is verified (pid 407 at 20.026 gpu_ms_per_sec over 1.22 s, and a 27-entry table in-process). The rescale of those ms/sec so their sum matches system GPU-busy is read-but-not-run in every proposal. ms/sec is the load-bearing column; the percent is derived, marked, and never used as the primary sort key.

One arithmetic correction carried forward: pricing 1-hour cache writes at the 5-minute rate understates them by **37.5%** for `claude-opus-5` ($6.25/M against $10/M), not the 60% the winning proposal claimed.

## Feature tiers

### v0.1 — MVP (what makes it usable daily)

- **SoC panel at mactop depth**: per-cluster gauges built by iterating reported topology (never hardcoded E/P), GPU utilisation and frequency, ANE, CPU/GPU/ANE/DRAM/system power in watts, CPU and GPU temperatures, fans, thermal state, memory and swap, network throughput, disk I/O. DRAM/ANE bandwidth render as a dash where the channel does not resolve.
- **Live sessions table** for Claude Code and Codex CLI: status (busy / waiting / stale / unknown / rate-limited), agent, model, cwd, context-fill gauge, tokens in / out / cache-read / cache-write, session-total $, burn rate $/hr, tool-call count, subagent count.
- **Per-session CPU / GPU / RSS joined by pid**, read in the same instant by the same goroutine as the SoC sample. GPU as ms/sec.
- **Session detail view**: per-session tool-call histogram and recent tool log, subagent tree with resolved model ids and live/finished state, token breakdown, per-session cost.
- **Four named themes** as data files, selected by `--theme` or `WATTOP_THEME`, cycled in-app, mapped through semantic Roles.
- **`--json` headless output** plus `--once` for a scriptable single snapshot.
- **`doctor` subcommand** reporting which IOReport channels and collector fields actually resolved on this chip.
- Honest labelling throughout: Claude context-fill marked approximate, Codex exact; costs marked as estimates that ignore subscription plans; unpriced models render `$—`, never `$0.00`.

### v0.2

- History sparklines for CPU / GPU / watts / $ per hour on a shared x-axis (braille via ntcharts, on top of the `panel/spark.go` helper and the history rings both landed in v0.1).
- `wattop record --dur 60s --out <dir>` — an in-binary fixture recorder writing a timestamped `SysSample`/`ProcSample` sequence plus agent records scrubbed through `internal/fixture`. Cut from v0.1 because `cmd/wattop-scrub` and `scripts/fixtures.sh` already capture the corpus, and a second capture path is a second thing to keep correct.
- Claude 5-hour block tracking and rate-limit views; Codex `rate_limits.{primary,secondary}` gauges promoted from the detail pane to the header.
- Gemini CLI and OpenCode session parsers behind the existing `AgentSource` interface.
- Prometheus exporter (`--prometheus :PORT`) emitting both halves on one scrape.
- tmux / iTerm2 jump-to-session from a selected row.
- macmon as a second `Sampler` implementation, as a cross-check oracle on chips other than M5 Max and a fallback if the vendored ObjC stops building.

### Later

- Menubar companion.
- Alerts and thresholds (burn rate above $X/hr, context above 90%, thermal state change).
- Remote hosts: an agent mode exporting `Snapshot` over the network, and a multi-host view.
- Session attach / kill controls.
- Intel and non-M5 tuning once fixtures exist from other chips.

# Task 2: Domain types and collector interfaces

**Files**

- `internal/domain/types.go`
- `internal/domain/snapshot.go`
- `internal/domain/interfaces.go`
- `internal/domain/types_test.go`

**Spec**

Define every type that crosses a collector boundary. **This package is the fixture boundary: nothing above `internal/soc` or `internal/proc` may ever name a vendored or third-party type.** The rule exists because a dependency's type can be serialise-only — macmon's `Metrics` derives `Serialize` with no `Deserialize` and no `Clone`, which would silently destroy a replay story. Every type here is a plain struct with JSON tags, round-trippable through `encoding/json`, and safe to copy.

Optional metrics are **pointer-typed**. A channel that does not resolve on a given chip yields `nil`, which renders as a dash. Absent must never decode as zero — that is how a missing DRAM channel would masquerade as idle memory.

**Every exported field on every type in this package carries an explicit lower_snake_case JSON tag.** The sketch below abbreviates them; the implementation does not. `--json` output is the public headless contract and Task 13's acceptance greps it with `jq` for `.sys.soc_name`, `.sys.bandwidth.dram_read_gbs` and `.sessions`, so Go's default capitalised field names would fail those commands.

```go
type Cluster struct {
    Label      string   `json:"label"`       // "P", "S", "E" — from topology, never a constant
    CoreCount  int      `json:"core_count"`
    ActivePct  *float64 `json:"active_pct"`
    FreqMHz    *float64 `json:"freq_mhz"`
    CoreActive []float64 `json:"core_active"` // per-core, len == CoreCount
}

type Power struct {
    CPUWatts, GPUWatts, ANEWatts, DRAMWatts, SystemWatts *float64
}

type Bandwidth struct { // nil throughout on M5 Max as of 2026-09-06
    DRAMReadGBs, DRAMWriteGBs, ANECombinedGBs *float64
}

type SysSample struct {
    At           time.Time
    SoCName      string   // e.g. "Apple M5 Max"
    Clusters     []Cluster
    GPU          struct{ ActivePct, FreqMHz *float64; CoreCount int }
    Power        Power
    Bandwidth    Bandwidth
    Temps        map[string]float64  // "cpu", "gpu", "soc"
    Fans         []Fan
    ThermalState int
    Memory       MemorySample
    Net          NetSample
    Disk         DiskSample
    Missing      []string  // channel names that did not resolve; feeds `doctor`
}

type Fan struct {
    Label  string   // "fan0", or the SMC key label if one is reported
    RPM    float64
    MinRPM *float64
    MaxRPM *float64
}

type MemorySample struct { // bytes throughout, never MB or pages
    TotalBytes, UsedBytes, AvailableBytes uint64
    SwapTotalBytes, SwapUsedBytes         uint64
}

type NetSample struct{ InBytesPerSec, OutBytesPerSec float64 }

type DiskSample struct{ ReadBytesPerSec, WriteBytesPerSec float64 }

type RateLimit struct {
    Scope       string     // "five_hour" | "weekly" | Codex "primary" | "secondary"
    UsedPct     *float64   // Codex supplies this; Claude does not
    WindowMins  int
    ResetsAt    time.Time
    Rejected    bool       // true when the source was a Claude quotaLimits rejection
}

type ProcSample struct {
    PID          int
    Comm         string   // p_comm, truncated — display only, never a join key
    Argv         []string // KERN_PROCARGS2; the only reliable way to recognise a codex or claude process
    CWD          string   // proc_pidinfo(PROC_PIDVNODEPATHINFO); "" when unreadable
    RSSBytes     uint64
    CPUPct       float64  // from a delta of cumulative CPU ns over wall ns
    DiskReadB, DiskWriteB uint64 // RUSAGE_INFO_V4 ri_diskio_*
    StartTime    time.Time      // WALL-CLOCK process start, the Codex bind tiebreaker.
                                // Derived from ri_proc_start_abstime in Task 6 — never a raw
                                // Mach tick count; zero when it could not be derived.
    GPUMsPerSec  *float64
    GPUPctApprox *float64 // derived and labelled; never the primary sort key
}

type Usage struct {
    Input, Output, CacheRead     int64
    CacheCreate5m, CacheCreate1h int64
    Thinking                     int64
    CachedInput                  int64 // Codex only: a SUBSET of Input, not additive
}

type ToolCall struct{ Name string; At time.Time; ID string }

type Subagent struct {
    Hash, AgentType, Description string
    Model      string   // resolved id from the child jsonl, never the parent's alias
    ToolUseID  string
    SpawnDepth int
    Usage      Usage
    Live       bool
    CostUSD    *float64
}

type Session struct {
    Agent        string // "claude" | "codex"
    ID           string
    PID          *int   // nil for an unbound Codex rollout
    BindConf     string // "exact" | "inferred" | "unknown"
    CWD          string
    Name         string // from the session file, never from the process name
    Cmdline      string
    Kind         string // interactive | sdk-cli | exec
    Status       string // busy | waiting | stale | unknown | rate-limited
    StatusSince  time.Time
    Model        string
    Usage        Usage
    CostUSD      *float64
    BurnUSDPerHr *float64
    Priced       bool
    ContextUsed  int64
    ContextMax   int64
    ContextExact bool // true for Codex (from the transcript), false for Claude
    Tools        []ToolCall
    ToolCounts   map[string]int
    Subagents    []Subagent
    Proc         *ProcSample
    RateLimits   []RateLimit
}

type Snapshot struct {
    At           time.Time
    Sys          SysSample
    Sessions     []Session
    TotalCostUSD float64
    TotalBurnUSDPerHr float64
    UnpricedModels []string
    Degraded     []string // per-source failure badges from recover()
    SelfCPUPct   float64
}
```

`internal/domain/interfaces.go` declares the three collector seams and nothing else:

```go
type Sampler interface {
    Init() error
    Sample(ctx context.Context, intervalMs int) (SysSample, error)
    ThermalState() int
    Channels() map[string]bool // for `doctor`
    Close() error
}

type ProcSource interface {
    Scan(ctx context.Context) ([]ProcSample, error)
    Close() error
}

type AgentSource interface {
    Name() string
    Poll(ctx context.Context, now time.Time, procs []ProcSample) ([]Session, error)
    Close() error
}
```

**`Poll` takes the process table as an argument, and that is load-bearing.** Codex has no per-pid session file, so binding a rollout to a pid needs each candidate's argv, cwd and start time — and passing them in rather than having the source read them keeps `internal/agent/*` free of syscalls and therefore testable on Linux CI. Four places implement or call this signature and all four must use the three-argument form: `replay.NewAgentSource` (Task 4), `claude.Source` (Task 8, which ignores `procs`), `codex.Source` (Task 9, which needs it), and the agent-watcher goroutine in `cmd/wattop/run.go` (Task 13, which passes the newest `[]ProcSample` from the scanner).

`ProcSample.Argv` and `ProcSample.CWD` exist for that bind and for `Session.Cmdline`. They are not conveniences: `p_comm` for a live Claude pid is its *version string* (`2.1.261`) and for its Workflow children is `node`, so argv is the only way to recognise either agent from the process table.

Tests: for each top-level type, marshal a fully-populated value, unmarshal, and assert deep equality; and marshal a value with every pointer field nil, unmarshal, and assert the pointers are still nil (proving absent does not become zero). Add a test that marshals a fully-populated `Snapshot` and asserts the JSON contains the exact keys `sys`, `sessions`, `soc_name` and `dram_read_gbs`, so a missing tag fails here rather than in Task 13's `jq`.

**Spec**

Record real data from this machine, redact it, and commit it. Everything downstream is tested against these files, so they must be recorded before the parsers are written.

**One corpus, at the module root, reached through a helper — never a relative literal.** `go test` sets the working directory to the *package* directory, so a test in `internal/collect/replay` that opens `testdata/soc/mactop-ndjson.jsonl` resolves it to `internal/collect/replay/testdata/soc/…` and fails on a path nobody created. Tasks 4, 8, 9, 11, 12 and 14 all read this corpus from six different package directories, so `internal/fixture/corpus.go` exposes `CorpusDir() string`, which walks up from `runtime.Caller`'s file until it finds the directory containing `go.mod` and returns `<root>/testdata`, panicking with a clear message if it does not find one. Every consumer builds its paths with `filepath.Join(fixture.CorpusDir(), "soc", "mactop-ndjson.jsonl")`.

The helper lives in `internal/fixture` and **not** in a package called `internal/testdata`, which was the obvious name and is a trap: the go command skips every directory named `testdata` during wildcard matching. Measured on this machine with go1.27.0 — such a package still imports and still tests when named explicitly, but `go test ./internal/testdata/...` prints `matched no packages` and exits 1, and the `go vet ./... && go test ./...` CI gate in Task 1 would silently never build or test it. A package the gate cannot see is a package that rots.

The root `testdata/` directory holding the data itself is the standard pattern and stays. Package-local `testdata/` directories elsewhere in the tree are fine too, for golden files, which belong next to the code that renders them.

`internal/fixture` provides `Scrub(line []byte) ([]byte, error)`, a pure function that rewrites a JSON record:

- Replace `/Users/jasonmatthew` with `/home/u` everywhere it appears, in any string value or key.
- Replace human prose — Claude `message.content[].text` on user and assistant records, Claude `description` fields, Codex `event_msg.payload.last_agent_message`, Codex prompt text — with filler that preserves the **UTF-8 byte length**, not the rune count. For each rune in the original, emit `utf8.RuneLen(r)` copies of ASCII `x`, so `café` (5 bytes, 4 runes) becomes `xxxxx` and not `xxxx`. **The invariant is `len(Scrub(line)) == len(line)` on the raw line bytes**, because the thing that depends on it is Task 8's byte-offset tailer, which seeks and counts *file* bytes; a rune-count filler silently shortens every multibyte line and moves every offset the tailer tests assert on. - Rewrite UUIDs and session ids deterministically: a stable hash of the original mapped to a fixed-format uuid, so cross-record links (`parentUuid` → `uuid`, `toolUseId` → subagent meta) survive.
- **Preserve exactly**: every `usage` field, every `model` string, every tool `name`, every timestamp, `status`, `entrypoint`, `kind`, `model_context_window`, `rate_limits`. These are what the tests assert on.

# Task 6: `internal/proc` — per-pid CPU, RSS, disk and GPU

**Files**

- `internal/proc/scan_darwin.go` (`//go:build darwin && arm64 && cgo`)
- `internal/proc/scan_darwin.c`
- `internal/proc/gpu_darwin.go`
- `internal/proc/scan_stub.go` (`//go:build !(darwin && arm64 && cgo)`)
- `internal/proc/delta.go`, `internal/proc/delta_test.go`
- `internal/proc/scan_hw_test.go` (`//go:build hardware`)

**Spec**

A hand-written CGO process scanner — no gopsutil, no third-party dependency. Enumerate with `sysctl(KERN_PROC_ALL)`, then per pid call `proc_pidinfo(PROC_PIDTASKINFO)` for RSS and cumulative CPU nanoseconds, and `proc_pid_rusage(pid, RUSAGE_INFO_V4, …)` for `ri_diskio_bytesread`, `ri_diskio_byteswritten` and `ri_proc_start_abstime`. All of this is passwordless for own-user processes.

**`ProcSample.StartTime` is a wall-clock instant, and computing it is not a unit conversion.** `ri_proc_start_abstime` is a Mach absolute *tick count* on a monotonic clock with an arbitrary origin — usually boot. `mach_timebase_info` converts ticks to a *duration*, never to an epoch, so multiplying the raw start-abstime by the timebase yields "seconds since some unspecified origin" and comparing that to a UTC rollout timestamp (which is what Task 9's tiebreaker does) is comparing an age to a date. It silently produces bindings that look plausible and are wrong.

Anchor it instead. Once per scan — **not once per pid** — read `mach_absolute_time()` and `time.Now()` adjacently, and derive every pid's start time from that one anchor pair:

```
elapsed   := (nowTicks - ri_proc_start_abstime) * timebase.numer / timebase.denom   // nanoseconds
StartTime  = nowWall.Add(-time.Duration(elapsed))
```

Reading the anchor once per scan keeps every pid in a scan on one consistent basis and costs one extra syscall per scan rather than one per process; `RUSAGE_INFO_V4` is already being fetched for the disk counters, so the start-abstime itself is free. Guard the subtraction: if `ri_proc_start_abstime > nowTicks` (it should not happen, but a zero or garbage value does), leave `StartTime` as the zero `time.Time` and let Task 9 treat the candidate as unmatched rather than binding on a nonsense date.

Put the arithmetic in `delta.go` as a pure function so it is testable without hardware:

```go
// StartWall converts a Mach start-abstime to a wall-clock instant using an
// anchor pair (nowTicks, nowWall) read adjacently in the same scan.
// numer/denom come from mach_timebase_info. Returns the zero time when
// startTicks is in the future relative to nowTicks.
func StartWall(startTicks, nowTicks uint64, numer, denom uint32, nowWall time.Time) time.Time
```

The `//go:build darwin && arm64 && cgo` scanner reads the anchor and the timebase and calls this; the function itself has no syscalls and no build tag.

**Also populate `Argv` and `CWD` on every `ProcSample`** — `sysctl(KERN_PROCARGS2)` for the argument vector and `proc_pidinfo(pid, PROC_PIDVNODEPATHINFO, …)` for the working directory, both best-effort: on a permission error leave the field empty and carry on rather than dropping the row. Task 9 has no other way to bind a Codex rollout to a pid, and `bind.go` is deliberately syscall-free so it can run on Linux CI; these two fields are what make that possible. Leaving them unfilled compiles fine and silently produces a Codex table where nothing ever binds.

`DiskReadB`/`DiskWriteB` are collected here and rendered only in the v0.1 detail pane (Task 12) — they are not a missing panel in the session table, they are deliberately not a table column.

`delta.go` holds the pure arithmetic, and this is where the tests live: `CPUPct(prevNs, curNs uint64, wall time.Duration) float64` computes `Δcpu_ns / Δwall_ns × 100`. **Never report a lifetime average** — a cumulative counter divided by process age reads flat and is the classic wrong answer here. The first scan produces no CPU percentage at all; it establishes the baseline.

**`p_comm` is truncated and Claude Code sets its process name to its version string** — a live Claude pid reports `2.1.261`, and its Workflow children report `node`. Any join or filter matching the string "claude" finds nothing. So: join by pid, take the display name from `~/.claude/sessions/<pid>.json`, and take the command from argv, never from `p_comm`. `Comm` is carried in `ProcSample` for display only and this constraint is a comment in the source.

`gpu_darwin.go` calls `soc.GPUProcessStats()` — the wrapper Task 5 exports over the vendored table — and computes the per-pid delta: two samples ≥1 s apart, differenced to ms/sec. **ms/sec is the verified, load-bearing number** (a probe measured pid 407 at 20.026 ms/sec over 1.22 s, from a 27-entry table). The rescale of those ms/sec so their sum matches system GPU-busy percentage lives in mactop's `gpuMetricsFromSoc` GPU-busy path and is **read-but-not-run in every proposal**: implement it, populate `GPUPctApprox`, and mark it derived in the type comment and in the UI. Do not write an acceptance command that validates a percentage nobody has validated. If the rescale divisor is zero or absent, leave `GPUPctApprox` nil rather than dividing by a stand-in.

`scan_stub.go` returns `ErrUnsupportedPlatform` so Linux CI compiles the tree.

Tests: `delta_test.go` is table-driven and pure — first-sample-yields-no-percentage, counter-wrap, zero wall time, a known 500 ms delta of 250 ms CPU yielding 50%. It runs on Linux.

`TestStartWall` lives there too and is written from **fabricated** `(ticks, wall)` pairs, no hardware involved. With the Apple Silicon timebase (`numer=125, denom=3`, i.e. 125/3 ns per tick) and an anchor of `nowTicks = 1_000_000_000`, `nowWall = 2026-09-06T00:00:00Z`: a `startTicks` of `1_000_000_000 - 240_000_000` is 240e6 ticks = 10 s earlier, so `StartWall` must return `2026-09-06T00:00:00Z − 10s`. Add the equal case (`startTicks == nowTicks` → exactly `nowWall`), and the guard case (`startTicks > nowTicks` → zero `time.Time`). **The test that matters is the negative one**: assert that a `startTicks` value naively multiplied by the timebase and read as a Unix epoch would land decades away from the anchor, so an implementer who skips the anchor cannot pass.

`scan_hw_test.go` (`//go:build hardware`): scan twice 1 s apart and assert at least one process reports nonzero CPU%, that this test's own pid appears with nonzero RSS, and that `StartTime` is a plausible wall-clock instant — after `time.Now()` minus the machine's uptime (from `sysctl kern.boottime`) and before `time.Now()`. Assert it for **pid 1**, whose start time must be within a few seconds of boot; that one assertion fails loudly if the epoch anchoring is wrong, where a short-lived test process's own start time would not.

That URL is what `scripts/pricing.sh` and `refresh.go` both fetch; pin it in one exported `const SourceURL` and reference it from both. It carries bare keys for every model on this machine — `claude-opus-5`, `claude-fable-5-1`, `claude-sonnet-5`, `claude-haiku-4-5`, `gpt-5.6-terra`, `gpt-5-codex` — and it is the only source carrying `cache_creation_input_token_cost_above_1hr`, which is exactly what `cache_creation.ephemeral_1h_input_tokens` needs. models.dev collapses cache-write to one number; pricing 1-hour writes at the 5-minute rate understates them by **37.5%** for `claude-opus-5` ($6.25/M against $10/M).

That file is the documented update path: it states where the table comes from, how to refresh it, how to verify the checksum, and how to add a model that upstream has not yet published. The snapshot is embedded with `go:embed` so first run is correct offline and instant.

`refresh.go` performs an **async, non-blocking** refresh on start into `$XDG_CACHE_HOME/wattop/pricing.json` with a 24 h TTL. A stale cache is used rather than blocking; any failure is logged to the footer and is non-fatal.

`resolve.go` walks: exact key → strip a bracketed suffix (`claude-opus-5[1m]` → `claude-opus-5`; **zero of the 3,561 keys contain a `[`**, so this step is mandatory) → strip a trailing `-YYYYMMDD` date → try `anthropic.`/`openai.`-prefixed forms → longest-prefix match. A model that resolves to nothing sets `Priced = false`; the row renders `$—` and the model name is appended to `Snapshot.UnpricedModels` for a footer count. **Never render `$0.00` for an unknown model.**

`cost.go` computes, per assistant record:

```
input×input_rate + output×output_rate
  + cache_read×cache_read_rate
  + ephemeral_5m×cache_creation_rate
  + ephemeral_1h×cache_creation_above_1hr_rate
```

Thinking tokens are already inside `output_tokens` — do not double-count. For Codex, `cached_input_tokens` is a **subset** of `input_tokens`, proved arithmetically from a real record (`total 230377 = input 227924 + output 2453`, with `cached 210432` not added in), so `billable_input = input − cached_input`. Getting this backwards roughly doubles every Codex figure.

**Tier selection is driven by the keys present in the table, never by hardcoded tier names.** For each base cost key, scan the entry for `<key>_above_<N>_tokens` variants, sort the thresholds, and select by the request's own prompt size. This matters because `gpt-5.6-terra` genuinely carries `*_above_272k_tokens` rates while `claude-opus-5` carries **no** `*_above_200k_tokens` key at all — an implementer told "apply the 200k Anthropic tier" would build logic for a field that does not exist.

`burn.go`: burn rate is the derivative of cumulative session cost over a 60 s sliding window of transcript deltas, smoothed with an EWMA (α≈0.3), reported as $/hr. A session with no new records inside the window reports `$0.00/hr`, **not** the last nonzero value.

# Task 8: `internal/agent/claude` — sessions poller, transcript tailer, subagent walker

**Spec**

Implement `domain.AgentSource` for Claude Code. Everything here is a pure function over `[]byte` or over a `(path, offset)` pair — **no collector in this package spawns a process or makes a syscall beyond `stat`, `open`, `seek` and `read`**, which is what makes it fully testable on Linux CI.

`sessions.go` polls `~/.claude/sessions/`. The directory carries one small JSON file per live process keyed by OS pid: `{pid, sessionId, cwd, status: busy|waiting, kind, entrypoint: cli|sdk-cli, updatedAt, statusUpdatedAt, name, bridgeSessionId}`. This is the pid→session→cwd join with no cwd-sanitising needed, and it answers "is this session working right now" without opening a multi-MB transcript.

Two rules are non-negotiable and both are tested:

1. **Never open `<pid>.<hash>.key` — those are auth secrets for the messaging socket.** Enforce with a *positive* filename allowlist `^\d+\.json$`, not a blocklist, so a future filename shape cannot leak in. The test plants a fake `.key` file in a temp dir and asserts the walker did not open it.
2. **A session file with no `status` field renders `unknown`, never `waiting` and never idle.** This is real — pid 99571 on this machine has no `status` key at all.

`tail.go` is the offset tailer, shared in shape with Task 9. State is `{path, inode, offset}`: open, `Seek(offset)`, read complete lines only, advance the offset, close. Reset to offset 0 when the size shrinks or the inode changes. A trailing partial line is buffered, not parsed, and is retried on the next poll. Poll by `stat` for size and mtime on the shortlist of live-session files and read only the delta — **not fsnotify**; kqueue firing reliably on append is unproven, and a 500 ms stat of a handful of small files is free. Never re-read a whole multi-MB file.

`parse.go`: `ParseRecord([]byte) (Event, error)` over the transcript at `~/.claude/projects/<cwd with '/' → '-'>/<sessionId>.jsonl` — a *sibling* of the `<sessionId>/` directory, not inside it. A `quotaLimits` record with `rateLimitType: "five_hour"` sets the session status to `rate-limited` with the reset time — Claude gives no continuous rate-limit gauge, only this error record, so it is a banner and not a bar.

**Context fill is an estimate and the UI must say so.** The numerator is proved: the newest assistant record's `input_tokens + cache_read_input_tokens + cache_creation_input_tokens` (114,274 on a live session). The denominator is genuinely unavailable — a walk of every nested key across 12 recent transcripts found nothing matching context/window/limit/max_token/budget, and `message.model` is bare `claude-opus-5` even in a session whose real id carries a `[1m]` suffix, so LiteLLM's `max_input_tokens: 1000000` would render an actually-57%-full 200k session as 11%. Algorithm: `window = the smallest entry of a fixed tier ladder that is ≥ the observed high-water-mark prompt tokens`, self-correcting upward as a session grows. **The ladder is a package constant `[]int64{200_000, 500_000, 1_000_000}`, not a lookup.** Do not consult the pricing table for the ceiling: this package does not import `internal/pricing` and must not start doing so, and the sentence above is why `max_input_tokens` would be the wrong ceiling even if it did. Honour a per-session override supplied by the caller (Task 13 reads it from config, keyed by session id or cwd) — `Source` takes the override map as a constructor argument.

`subagents.go` walks `<sessionId>/subagents/`, pairing `agent-<hash>.meta.json` (`{agentType, description, toolUseId, spawnDepth, model}`) with `agent-<hash>.jsonl`. **Cost accounting uses the jsonl's `message.model`, not meta.json's `model`** — meta shows the requested alias (`opus`) while the child transcript carries the resolved id (`claude-opus-5`). A subagent is live when its jsonl is growing *and* the parent's `tool_use` block with `id == toolUseId` has no matching `tool_result` yet; that back-link is also what assembles the tree.

**`Poll` emits only the sessions that exist right now, and that is deliberate.** When a Claude process is killed its `~/.claude/sessions/<pid>.json` disappears, so the next poll simply does not return that session. Do **not** implement a grace period, a last-seen map or a `stale` transition here — Task 10's reducer owns session retention because it already holds the previous cycle's state, and a second TTL in this package would fight it. This source never emits `Status == "stale"` for a vanished session; it emits nothing for it, and the reducer turns that absence into a `stale` row and then removes it.

The earlier draft's `Reduce(…, prev *domain.Snapshot, …) domain.Snapshot` could not implement its own history rings: `domain.Snapshot` has no history fields and this task may not add any. The `State` receiver is the fix, and it also absorbs `book` and `burn`, which the old signature threaded through every call. The rationale for threading them has not changed — `domain` never imports `pricing`, so `domain.Snapshot` cannot own the burn tracker — it is just satisfied at construction now instead of per call.

**"Pure" here means no I/O and deterministic given `(st, in)`**, not functionally pure. `Reduce` mutates `st` (rings advance, `burn.Observe` records) and that was already true of the old signature, which called `burn.Observe` on a caller-owned tracker. The purity the acceptance grep enforces — no file, process, network or sleep — is unchanged.

**pid is the spine.** `~/.claude/sessions/<pid>.json` gives pid → sessionId → cwd → model; the process scan gives that pid its CPU%, RSS and disk I/O; the GPU table gives it ms/sec; the SoC sample gives machine-wide watts for the same instant. That is the join the whole product exists for, and it works because one goroutine reads all of it at one moment — two tmux panes structurally cannot say "GPU is at 84% and 31 W, and it is *that* session". **`Inputs.At` is what makes "the same instant" true rather than aspirational**: Task 13's coordinated cycle stamps one time onto the whole bundle, and this reducer copies it to `Snapshot.At` and to `Snapshot.Sys.At`, overwriting whatever the sampler wrote. Never derive `At` from `time.Now()` here — a reducer that reads the clock is no longer deterministic and the e2e virtual clock in Task 14 stops working.

Responsibilities:

- Attach each session's `ProcSample` by pid; leave `Proc` nil where the pid is unbound and render a dash rather than a zero.
- Price every session and subagent through the `book` held in `State`, aggregating `TotalCostUSD` and `TotalBurnUSDPerHr` via `burn.Observe` then `burn.RatePerHour`, and collecting `UnpricedModels`.
- Maintain per-session and machine-wide history rings (fixed capacity, ~300 samples) for CPU, GPU, watts and $/hr, read back through `History`. Already populated in v0.1 so the data exists when v0.2's charts land.
- **Retain vanished sessions for a `sessionTTL` of 30 s** (an unexported package constant — not a config key; Task 13's config already carries a Codex stale threshold and a second knob for this would be scope creep). Keep a last-seen map keyed by `(Session.Agent, Session.ID)` — **not by `ID` alone**, since `Inputs.Sessions` is the concatenation of the Claude and Codex sources (Task 13, step 4) and nothing guarantees their id spaces are disjoint — holding `(Session, lastSeenAt)`. A key present in `Inputs.Sessions` refreshes its entry and **keeps the status its source supplied** — this must not clobber Codex's own mtime-derived `stale` (Task 9). A key that was present in the previous cycle and is absent from `Inputs.Sessions` is re-emitted with `Status = "stale"` and `StatusSince` set to the `At` of the cycle it vanished in, so Task 12 can render the age; it is dropped entirely once `in.At.Sub(lastSeenAt) > sessionTTL`. This is the whole implementation of the "stale then drops" lifecycle the v0.1 feature tier and Task 14's QA step 3 promise. Task 8 emits only live sessions and deliberately implements none of it.
- **Set and clear `Snapshot.Degraded` from `Inputs.Health`** — this is the only route collector failures have into a `Snapshot`, since `Reduce` never calls a collector and cannot observe a panic itself. For each entry with `OK == false`, append a badge naming the source and its `Err`. For each entry with `OK == true`, emit nothing: **recovery is a badge that disappears on the next cycle**, so never carry a badge forward from `st`'s previous snapshot. # Task 13: `cmd/wattop` — wiring, headless JSON, doctor and config

**Files**

- `cmd/wattop/main.go`
- `cmd/wattop/run.go`
- `cmd/wattop/json.go`
- `cmd/wattop/doctor.go`
- `cmd/wattop/config.go`
- `cmd/wattop/run_test.go`

(`record.go` was cut from this task and moved to v0.2. It is absent from the v0.1 feature tier, and it duplicates a capture path Task 3 already ships as `cmd/wattop-scrub` plus `scripts/fixtures.sh`. Two fixture-capture implementations is one too many, and dropping it brings this task back under budget.)

**Spec**

Wire the collectors to the UI. **There is exactly one producer goroutine and it runs one coordinated sampling cycle.** This is what makes the product's central claim — SoC watts and agent dollars read at the same instant, joinable by pid — true rather than aspirational. Three independent tickers cannot support it: a process scan taken before a burst gets reduced against a SoC sample taken after it, and the row then attributes one session's CPU to a different moment's watts. Nothing in the render would show the skew.

The cycle, in one goroutine, in this order:

1. `sys, errSys := soc.Sample(ctx, intervalMs)` — **this call blocks for the full interval inside C**, which is what makes the power and bandwidth deltas accurate, and it is therefore also the cycle's pacing mechanism. There is no separate ticker; the block *is* the period.
2. `procs, errProc := proc.Scan(ctx)` — the table scan plus the GPU-ns delta, taken immediately on return from that block.
3. `at := time.Now()`, read **once**, here: after the two collectors that actually take time, and before the agent polls, which are stat-and-read-delta over a handful of small files and cost well under a millisecond.
4. `sessions` = `claude.Poll(ctx, at, procs)` concatenated with `codex.Poll(ctx, at, procs)`, both given this cycle's own `procs` from step 2 and `at` from step 3. That is what makes Codex binding work (Task 9), and no mutex or "most recent published scan" is needed any more, because there is no second goroutine to race with.
5. Build one `state.Inputs{At: at, Sys: sys, Procs: procs, Sessions: sessions, Health: health}` and send it as **one** `CycleMsg` through `p.Send()`. One message per cycle, not three; Task 12's `Update` calls `st.Reduce(in)` on it and renders.

`Inputs.At` is the single stamp the reducer copies onto `Snapshot.At` and `Snapshot.Sys.At`, so every field in a snapshot is attributable to one moment by construction rather than by hope.

**`--interval` is the SoC block duration and therefore the cycle period.** Step 1 passes it straight to `soc.Sample(ctx, interval)`, so the floor is whatever produces usable power deltas, not an independent UI refresh rate. The agent half deliberately no longer refreshes faster than the system half — that 500 ms agent ticker was the earlier draft's design and it is exactly the skew this cycle removes. Status flips are still visible within one interval, which at the 1 s default is the responsiveness the split design offered, minus the unjoinable samples.

**Health is produced here, per source, and handed to the reducer as `Inputs.Health`.** Steps 1, 2 and 4 each run under `recover()` and each yield one `state.SourceHealth`: `{Name: "soc", OK: errSys == nil, Err: …, LastOK: …}`, and likewise for `proc`, `claude`, `codex` and `pricing`. **A panic or error in one step does not abort the cycle.** It records `OK:false`, leaves that step's value as its zero — an empty `[]domain.ProcSample`, the previous `SysSample`, no sessions from that agent — and the cycle continues to step 5, so the dashboard keeps rendering with a badge instead of going blank. The reducer sets `Snapshot.Degraded` from this slice and clears it on the first cycle where the source reports `OK` again (Task 10); this is the only route a collector failure has into a `Snapshot`, since `Reduce` calls no collector and cannot observe a panic itself. Re-initialise a failed source with backoff between cycles, and **never let one failing source stop the loop** — the loop is now the whole clock.

**Startup is honestly empty for about two seconds, and that is not a bug to file.** Task 6's first scan establishes a CPU baseline without reporting percentages, so cycle 1's `procs` carry `CPUPct == 0` and cycle 1's agent polls have nothing useful to bind against. Every Codex row therefore renders `(pid unknown)` with dashes until cycle 2 lands, roughly two intervals in. Claude rows are unaffected — their pid comes from the session file, not the process table. Do not paper over this with a spinner that implies work; the dashes are correct.

`--json` prints one `domain.Snapshot` per interval as NDJSON to stdout and never enters the alt screen; `--once` prints exactly one and exits. **`--once` therefore takes one full `--interval` before it prints anything**, because step 1 of the cycle blocks inside C for that long and there is no snapshot until it returns. That is not a hang and it is not worth a spinner; it is the price of the first sample being a real power delta rather than an instantaneous zero. Both are the headless contract, so `Snapshot`'s JSON shape is the public interface and is covered by a schema test.

`doctor` prints, without entering the TUI: the detected SoC and cluster topology, which IOReport groups and channels resolved and which did not (including the expected DRAM/ANE misses on this hardware), whether the process scanner and GPU table returned rows, how many Claude and Codex sessions were discovered and how many bound to a pid, the pricing table's source, entry count and age, and the resolved theme. Add `doctor --ioreport-groups` enumerating IOReport groups with channel counts — this is how a renamed DRAM channel gets found later instead of never.

`config.go` reads `$XDG_CONFIG_HOME/wattop/config.toml` with `github.com/BurntSushi/toml` (pinned in Task 1 — this is its only consumer): theme, interval, burn-rate hot threshold, Codex stale threshold, and per-session context-window overrides keyed by session id or cwd. The override map is passed into `claude.NewSource` (Task 8), which takes it as a constructor argument. A missing config file is not an error.

Flags: `--theme`, `--interval` (500 ms – 5 s; it is the SoC block duration and therefore the whole cycle period, so a shorter value means shorter power-delta windows, not a faster UI on top of the same sampling), `--json`, `--once`, `--no-color`, `--version`. Theme precedence, resolved once at startup and stated here because three tasks reference the theme and none of them owns this order: `--theme` > `$WATTOP_THEME` > `config.toml` > `wattop-dark`. An unrecognised name falls back to `wattop-dark` and prints a one-line warning; it is never fatal.

`cmd/wattop` constructs the single `pricing.Book` and `pricing.BurnTracker` and hands both to `state.New(book, burn)` **once at startup** (Task 10), then passes that one `*state.State` into the UI model. **Keep `cmd/wattop`'s own `*pricing.Book` reference after handing it over** — `doctor` needs `Entries()` and `Source()` and never goes through the reducer, which holds the book unexported. `domain` still never imports `pricing`, which is why `domain.Snapshot` cannot carry either; `state.State` can, and holding them there is what removes them from the per-cycle call.

Startup failure is soft and specific: if `soc.Init()` fails, print a one-line banner naming the error and run with the session half only. Never hang on "Loading…", and never require sudo.

`run_test.go` asserts the flag surface parses; that `--once --json` against replay sources emits exactly one valid `Snapshot` line; that a panicking fake collector produces a `Degraded` badge rather than terminating the run loop, **and that the badge clears on the next cycle once that collector stops panicking** (the recovery half — a badge that never clears is a different bug wearing the same shirt); and that one cycle over replay sources produces a `Snapshot` whose `At` equals its `Sys.At`, which is the coordinated-cycle property asserted end to end rather than only inside the reducer.
